# 日文練習 PWA V1.5.10

## V1.5.10 — 精簡版面與加密設定備份（2026-10-23）

- 首頁修正兩欄容器與舊跨欄規則衝突，縮短卡片留白及重複的學習範圍文字；手機保留貼底導覽，桌面使用並排摘要與推薦詞。
- 導覽、首頁捷徑、發音、筆順、設定分類、匯入／匯出使用一致的線條圖示。設定保留「帳戶與雲端」為第一組，減少內層卡片；平板／桌面資料庫採雙欄列表。
- 設定最下方新增「加密設定備份」，位於「資料保存」之後，提供匯出及匯入。
- 一次匯出已儲存的 Google OAuth Client ID、Drive 資料夾 ID、自動同步偏好、Gemini API Key／模型、JLPT、每日推薦兩種假名行別、各練習模式選項、發音開關／延遲、上次練習模式與單字排序。
- 使用瀏覽器 Web Crypto 的 AES-256-GCM 與 PBKDF2-SHA256（600,000 次），每次產生隨機 16-byte salt 與 12-byte IV。密碼至少 12 個字元，密碼不儲存；檔案副檔名為 `.jpsettings`，內容不是明文設定。
- 匯入先檢查大小、版本及格式，解密後顯示遮蔽 API Key 的預覽，按「確認還原設定」才以 IndexedDB 單一交易套用。錯誤密碼、被修改的檔案或不支援的格式不會改寫設定。
- Google 存取權杖、登入工作階段、裝置通知訂閱／時間與學習紀錄不包含在設定檔中；通知仍維持原裝置設定。單字、例句與練習紀錄使用原有資料備份。更換 OAuth Client ID 後，需在本機重新連結 Google。
- Drive 資料夾明確留空時會維持根目錄，不再被內建預設 ID 覆蓋。尚未設定的裝置仍沿用原始預設值。
- 保留啟動自動檢查更新、設定頁目前／最新版本及手動檢查按鈕。離線資源包含新模組，版本與快取一致。資料結構及通知後端不變，不需重新初始化 D1。

### 使用加密設定備份

1. 先將修改過的 Drive、API Key 等欄位按「儲存」。
2. 設定頁滑到最底 →「匯出加密設定」，輸入並確認至少 12 個字元的備份密碼。
3. 按「加密並下載」，確認檔案已存入下載資料夾；iPhone／iPad 可使用畫面提供的下載連結儲存檔案。密碼遺失無法復原此備份。
4. 還原時選「匯入加密設定」，選取 `.jpsettings`、輸入密碼，確認預覽後再按「確認還原設定」。不會刪除單字或練習歷史。

加密保護下載檔案；App 本機仍沿用既有儲存方式。請將密碼與檔案分開妥善保存。此版並未把一般學習資料備份改成加密格式。

### 驗證與更新

- 語法與完整 184 項自動測試通過；涵蓋加密往返、錯誤密碼、檔案竄改、大小限制、設定白名單及交易式還原。
- Chromium 檢查 320×640、430×932、820×1180、1280×800 的首頁、設定、練習、資料庫、統計頁；底部導覽及水平溢出檢查通過。實際操作設定匯出、錯誤密碼、解密預覽及確認還原通過。
- iPhone／iPad 真機的下載儲存選單、鍵盤與語音，以及真實 Google／Gemini 帳戶仍須實機驗證。測試未使用個人金鑰。

解壓後，ZIP 內只有一層同名資料夾。需要自行發布時，將該資料夾**內**的檔案放在 Repository 根目錄，使 `index.html` 位於根目錄。不要上傳外層資料夾、`node_modules` 或先刪除網站資料。這次沒有替使用者寫入 GitHub 或 Cloudflare。

更新前先在設定頁匯出救援備份。更新後檢查首頁及設定頁版本都是 V1.5.8，並實測上傳成功、取消傳輸、設定順序與一輪練習。現有 IndexedDB、Google OAuth 設定、D1 綁定及 VAPID Key 不因本版改變。

本次只需更新前端檔案。不要因前端版本更新重新建立 D1 或重新產生 VAPID 金鑰；通知後端未改動。

## 本機檢查

Node.js 20 以上：

```bash
npm ci
npm run check
npm test
```

前端是靜態檔案，不需要 npm build。Worker 設定見 `wrangler.toml`；已建立 D1 的使用者不要為前端更新重新建立資料庫或更換 VAPID 金鑰。

真實 Gemini Key、Google 帳號、Drive 寫入、Cloudflare 推播及 iOS 真機鍵盤／手寫／通知，需在使用者環境另外驗證。金鑰、access token、VAPID 私鑰不包含在 ZIP 或備份中。Google 工作階段失效時可能需要再次授權。
